## Known issues and technical debt

- Dependency update pull requests require compatibility checks against the pinned Go and Node runtimes.
- The dashboard polls alerts only while visible on the latest page. Background release email requires explicit SMTP configuration and owner consent. Opt-in browser delivery is implemented and requires production provider configuration and owner consent. Identity SMTP serves account verification and recovery.
- Starter catalog, source coverage and curated feature coverage are limited. Discovery supports evidence coverage and unfamiliar-feature ordering. Global Essentials has an offline ranker, evaluator and opt-in PostgreSQL dashboard lane. The lane requires a reviewed canonical-ID manifest. Use catalog details to ask deterministic questions about sourced fields, continuity and recorded release facts. Model-assisted topic selection is available with explicit operator configuration and verified-owner opt-in. Private Discovery reactions can contribute to Personal Match when a feature has no declared or rating-derived signal. Representative evaluation and broader analyst tools remain open.
- Some historical runbook entries describe their original migration level. Apply all embedded migrations and current grants on new databases.
- Reviewed merges are available for unused placeholders. Merges that need dependent-data correction and generalized event retraction remain open. Operator approval and source provenance are prerequisites for wider catalog activation.
- Recovery and restricted role behavior are exercised on synthetic databases. Public ingress controls, an independent security review, production monitoring, real backup/key distribution and recovery objectives remain open. See [security](SECURITY.md), [identity security](docs/IDENTITY_SECURITY.md) and [backup recovery](docs/BACKUP_RECOVERY.md).

Improve Discovery exploration using the offline ranking/retrieval evaluator.

3. Expand catalog coverage through explicitly reviewed source capabilities and permissions, using the offline feed field-presence report and assessing field accuracy separately. Treat the current adapters and operator tools as the integration path.
4. Continue production hardening and independently verify authorization, abuse controls and recovery. Public deployment and live source credentials require an authorized environment. Continue synthetic/local work while those dependencies are pending.
